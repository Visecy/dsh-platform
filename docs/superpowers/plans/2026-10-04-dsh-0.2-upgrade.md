# Plan 3：DSH 0.2.0-rc.2 升级 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把平台从 DSH `0.1.5-rc.1` 升到 `0.2.0-rc.2`（npm `latest`），保持零编译产物补丁、零 fork，并把会话持久化的 `SESSION_FORMAT_VERSION` 3→4 迁移做对。

**Architecture:** 不改变架构——升级之所以现在才做，是因为 Plan 1 已经把需要重锚的 vendored 代码（7 个 anchor）、webserver fork（1 行重同步）和 `patch-dsh.mjs`（keep-guard 重锚）全部删掉了。本计划只剩四件事：依赖升版、profile 行清单校正、`fs.watch` 补齐、v4 迁移。

**Tech Stack:** pnpm workspace、cordis 4、TypeScript、vitest、node:sqlite、PostgreSQL、helm。

## Global Constraints

- 控制面必须保持无状态、可 `readOnlyRootFilesystem` 运行；持久状态只能在 Postgres。
- **不引入任何编译产物补丁或 fork**：只用官方公开 API。
- 会话持久化必须能读 **v3 旧库**（金标准夹具 `packages/session-persistence-rdb/tests/fixtures/v3-golden.sql` 是硬约束，升级后**无法再生**）。
- `packages/session-persistence-rdb` 的 `SCHEMA_VERSION` **保持 1**：v4 迁移只需一个索引，不需要新表/新列（见调研文档 §3）；若有人提议改 schema，必须先说明为什么索引不够。
- 工作区插件与身份解耦的契约不得破坏。

## 前置事实（已核实，不要重新调研）

- 0.2.0-rc.2 与 0.2.1-alpha.1 在 `session-format-v3-to-v4` 与 `session-persistence-jsonl` 上**字节相同**。
- 0.2.x 的文件查看路径**要求 `ctx.fs.watch`**；`FileSystem` 基类提供默认实现（reject `FS_IO_ERROR`），调用方会转成 `workspace-file/watch-unsupported` 并**抛错**。0.1.5 完全没有这个调用。
- `ui-workspace` 在 0.2.x **没有工作区行的槽位**（`ProjectRowItem` 无 `renderSlot`，bundle 只导出 `apply`/`inject`）；新增的四类子槽位都是**会话行**作用域。`main`(keyed) / `sidebar.panellist` / `shell.overlay` / `sidebar.footer.action` 可用。
- profile 的 10 个 disable id 在 0.2.x **全部仍然存在**；但有 3 行被移除、32 行新增、`ui-schedule` 由禁转启、若干 name/config 变化。
- **`web-runtime` 行是整段替换 config**：必须补上 0.2.x 新增的 `publicUrl`，否则跳转地址会静默回落到 loopback。

### Task 2: `fs-k8s` 实现 `FileSystem.watch`

**Interfaces:**

- [ ] **Step 1:** 先写失败测试：在假 daemon 上 `watch()` 一个目录，改动后必须在超时内收到 `changed()`；`close()` 后再改动**不得**再回调；`signal` 中止时初始化必须拒绝。

### Task 3: `session-persistence-rdb` 的 v3→v4 迁移

**Files:**
- Create: `packages/session-persistence-rdb/src/catalog.ts`
- Modify: `src/entities/sessions.ts`（**只加一个索引**）、`src/migrate.ts`、`src/backend.ts`、`src/sqlite.ts`、`src/postgres.ts`、`src/index.ts`、`package.json`（peer 版本）
- Test: `src/__tests__/v4-migration.spec.ts`（新建）+ 既有 `fixture-restore.spec.ts` 必须保持绿

**Interfaces（来自调研文档 §1/§3，逐字）:**
- child fact 形状：`{ childId: string; childCreatedAt: number; descriptorCount: number; descriptor: JSON | null; sourcePath?: string }`，**每个父一个数组**，无子必须传 `[]`。
- 新索引：`ix_sessions_subagent_parent (f_parent_session, f_origin)`。
- 发现查询：`WHERE f_parent_session = ? AND f_origin = 'subagent' ORDER BY f_created_at, f_session_id`；`descriptorCount` 必须取自被解码子日志的 `artifact.inheritedEventCount`，**不要在 SQL 里重新推导 cut**。
- 绑定方式：`createSessionFormatCatalogWithChildren(facts)`。

- [ ] **Step 1:** 先写失败测试：用金标准 v3 夹具（`tests/fixtures/v3-golden.sql`）挂载后端并读取 `parent-1`，断言**不抛** `SessionFormatUnsupportedMigrationError`，且迁移后 header.version 为当前版本；断言 `child-1` 的 facts 按上述形状被采集。
- [ ] **Step 2:** 跑测试确认失败（当前静态 catalog → 抛 `V3 catalog migration requires explicit historical child facts`）。
- [ ] **Step 3:** 实现 `catalog.ts`（选择器 + `factFromArtifact` + `unavailableFact`），`migrate.ts` 接受 `childFacts` 并用子绑定 catalog，backend/sqlite/postgres 增加 `listChildSessions` 与索引。
- [ ] **Step 4:** 跑测试确认通过；**尤其确认 `fixture-restore.spec.ts` 仍绿**（v3 读路径不能被破坏）。
- [ ] **Step 5:** 补测边界：子行被删（identity-only fact + `mode:'unknown'`，父仍可迁移）、多子、无子的 `[]` 分支、以及"存储条目与实时子证据冲突时必须显式拒绝"。
- [ ] **Step 6:** 提交。
